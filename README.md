# Backrooms Escape

**하나가 쫓고 나머지가 빠져나가는, 2층짜리 백룸스 미로의 비대칭 술래잡기 FPS.**

브라우저에서 도는 Unity WebGL 클라이언트와, 이동과 전투를 판정하는 .NET 서버가
한 저장소에 함께 있습니다.

**플레이**: <https://play.nhn-backroom.kro.kr> (서버 `api.nhn-backroom.kro.kr`)

```
NVproject/   Unity 6.3 (6000.3.20f1) WebGL 클라이언트 — URP, 새 Input System, IL2CPP
NVserver/    .NET 10 서버 — Kestrel, Minimal API, 30Hz 틱 루프, 모듈러 모놀리스
```

---

## 게임

한 사람이 **술래**, 나머지가 **러너**입니다. 역할은 매치가 시작될 때 정해집니다.

**러너**는 맵에 흩어진 열쇠를 모아 문에 꽂습니다. 필요한 개수는 인원이 정합니다 —
2인 3개, 3인 5개, 4인 8개, 5인 10개. 다 꽂으면 문이 열리고, **두 명이 빠져나가면
러너 승리**입니다(인원이 그보다 적으면 그 인원 수만큼).

**술래**는 총 세 발을 가집니다. 한 발 맞은 러너는 피를 흘리며 맵 어딘가로 튕겨
나가고, 두 발이면 쓰러집니다. 세 발을 다 쓰면 **사슬이 술래를 제단으로 끌고 가**
3초를 붙잡아 둔 뒤에야 재장전해 줍니다 — 세 번째 방아쇠는 걸어온 거리를 통째로
되돌립니다.

**8분 안에 목표 인원이 못 빠져나가면 술래 승리**입니다. 러너 전원이 쓰러져도
술래 승리입니다.

맵에는 한 번 또는 여러 번 쓸 수 있는 **장치 9개**가 흩어져 있습니다 — 시간 추가,
전체 위치 공개, 출혈 정지, 전원 정지 + 벽 투시, 술래 시점 보기, 순간이동.
술래는 그것을 **부술 수 있습니다**(4발). 러너의 도구인 동시에 술래에게는
"여기 누가 왔다 갔다" 는 흔적입니다.

### 비대칭이 곧 정보 규칙입니다

이 게임에서 두 진영이 다른 것은 능력이 아니라 **보이는 것**입니다.

| | 러너 | 술래 |
|---|---|---|
| 탈출 문 | 보인다 | **보이지 않는다** — 좌표가 아예 전송되지 않는다 |
| 열쇠 진행도 | 보인다 | **0으로 지워져서 온다** |
| 피 흔적 | 자기 것만 | 전부 보인다 |
| 남은 탄약 | **모른다** — 총성으로만 안다 | 보인다 |
| 어둠 | 손전등을 든다 | 어둠에서 더 잘 본다 (손전등 없음) |
| 달리기 | 항상 가능 | **게이지** — 가득 4초, 1.6배속, 충전 10초 |

숨기는 방식이 **카메라 컬링 마스크가 아니라 와이어**라는 점이 중요합니다. WebGL
빌드는 디컴파일된다고 전제하므로, 문의 좌표는 술래의 사본에서 **빠진 채로**
나갑니다 — 화면에서 가리는 것이 아니라 계산할 입력을 주지 않습니다.

전체 규칙은 `NVproject/.claude/skills/game-rules/references/ruleset.md` 가
**진실의 출처**입니다. 코드의 숫자를 바꾸기 전에 그 파일을 먼저 바꾸세요.

## 실행

### 서버

```bash
cd NVserver
dotnet run --project Api      # http://localhost:5202  (ws://localhost:5202/ws)
```

맵 등록은 자동입니다 — `NVserver/MapData/*.json` 을 훑어 파일 이름 그대로
등록합니다.

### 클라이언트

**CLI 빌드가 없습니다.** 모든 작업은 Unity 에디터에서 합니다.

가장 빠른 길은 **Tools ▸ NV ▸ Build and Launch 2 Clients** — 윈도우 스탠드얼론
두 개를 굽고 띄웁니다. 두 창 모두 메인 로비에서 시작합니다.

1. 한쪽에서 **방 만들기** → 초대 코드가 나옵니다
2. 다른 쪽에서 그 코드로 참가
3. 게스트가 **READY**, 방장이 **START**

방장은 READY 를 누르지 않습니다 — **START 가 방장의 준비**입니다. 그 외에는
**전원이 READY 를 눌러야** 시작됩니다. 예외인 방은 없습니다.

최소 2명이 필요합니다(술래 1 + 러너 1). 한 방은 최대 5명입니다.

## 구조

### 두 프로젝트가 만나는 세 지점

나머지는 서로 독립입니다.

**1. `NVserver/Shared/` 는 Unity 로컬 패키지입니다.** 같은 `.cs` 파일을 IL2CPP
(netstandard2.1)와 net10.0 이 함께 컴파일합니다. 이동이 양쪽에서 **비트 단위로
같게** 계산되어야 하므로 이 어셈블리가 저장소에서 가장 엄격합니다 — C# 9,
NuGet 금지, `UnityEngine` 금지, `MathF.Sin`/`Vector3.Normalize` 금지
(`DeterministicMath` 를 씁니다).

**2. 맵의 원본은 클라이언트입니다.** 레벨은 씨드에서 코드로 생성되고, 서버는
익스포트된 박스 목록(`NVserver/MapData/*.json`)으로만 지형을 압니다. 씨드·격자·
벽 두께를 바꾸면 **Tools ▸ NV ▸ Map ▸ Export Map Collision** 을 다시 돌려야
합니다. 맵 해시가 이 결합의 유일한 감시자이고, 어긋나면 접속이 거절됩니다.

**3. 와이어 프로토콜은 `Shared/Contracts/Messages` 에 있습니다.** 바이너리,
opcode 우선, 리틀 엔디언. **현재 버전 5** — 불일치는 WebSocket 업그레이드
**전에** 426 으로 거절되므로, 클라이언트와 서버는 같은 커밋으로 배포해야 합니다.

### 서버는 판정하고 클라이언트는 그린다

이동·전투·목표물·시계가 전부 서버의 것입니다. 클라이언트는 **입력을 보내고 위치를
받습니다** — 자기 좌표를 주장하지 않습니다.

상태는 두 갈래로 내려옵니다:

- **스냅샷**(매 틱) — 몸의 위치와 `EntityFlags` 8비트. 출혈·탈출·쓰러짐처럼
  **즉시** 반영돼야 하는 것들
- **게시**(2Hz) — 매치 단계, 시계, 열쇠 수, 탈출 수, 탄약. HUD 가 반 초 늦어도
  되는 값들

게시는 **알림이 아니라 상태**입니다. 매 번 전부 다시 보내고 멱등합니다 —
세션 채널이 `Bounded(32, DropOldest)` 라, 한 번만 보내는 "매치가 시작됐다" 는
언젠가 버려지는 프레임이 되고 그 클라이언트는 영원히 로비 화면에 남습니다.
예외는 총성 알림(`FireEvent`) 하나뿐이고, 그 판단 기준은 ADR 0003 에 있습니다 —
**놓쳤을 때 잘못된 상태가 남는가?**

### 캐릭터는 코드로 만들어집니다

모델도, 스킨드 메시도, Animator 도, 애니메이션 클립도 없습니다. 마인크래프트풍
블록 인형을 `BlockRig` 가 런타임에 쌓고, 걸음·팔 스윙·반동·재장전을 전부 코드가
포즈합니다. 술래는 역할 공개 때 같은 관절 위에 **괴물 몸**으로 다시 조립됩니다.

발소리와 총성도 에셋이 아니라 **코드로 합성**합니다. 이 게임에서 소리는 술래의
주 감각이자 러너의 주 누출이라, 거리 감쇠 곡선이 밸런스 값입니다.

## 개발

```bash
# 서버
cd NVserver
dotnet build      # 경고 0개로 끝나야 한다 — TreatWarningsAsErrors 가 켜져 있다
dotnet test       # 678개 (Modules 674 + Architecture 4)

# 클라이언트 — 플레이어를 굽지 않고 타입 검사만
cd NVproject
dotnet build Assembly-CSharp.csproj
dotnet build Assembly-CSharp-Editor.csproj
```

클라이언트에 **새 `.cs` 를 추가하면 생성된 csproj 의 `Compile` 목록에 없어서**
자기 네임스페이스에서 `CS0234` 로 먼저 실패합니다. 에디터를 한 번 열면 다시
생성되고, 급하면 `<Compile Include="…" />` 를 손으로 넣으면 됩니다.

Unity 작업은 MCP 브리지(`mcp__unity-mcp__*`)로 합니다. 브리지에는 코드 버그처럼
보이는 실패 방식이 여럿 있으니 `NVproject/.claude/skills/unity-mcp-ops` 를 먼저
읽으세요.

### 규칙 두 가지

**서버 모듈은 서로를 참조하지 않고**, 모듈의 `Contracts/` 밖은 전부 `internal`
입니다. `tests/Architecture.Tests` 가 `ProjectReference` 선언을 읽어 이것을
검사합니다.

**상수의 집은 둘뿐입니다.** 클라이언트가 같은 계산을 해야 하면
`Shared/Simulation/SimConstants.cs`, 서버 혼자 정하면
`Modules/{Module}/{Module}Constants.cs`. 다른 값에서 유도할 수 있는 값을 다시
적지 마세요.

### 브랜치

`feature/{area}/{topic}`, 베이스는 `main`. 커밋 제목은 컨벤셔널 커밋 접두사
(`feat(realtime):`, `fix(client):`, `docs:`)를 씁니다.

30분 넘게 걸린 문제나 새로 정한 규칙은 `NVserver/docs/conventions.md` 에
**증상 → 원인 → 수정** 으로 남기세요. 그 파일이 이 저장소에서 가장 값이 큰
문서입니다.
