# ADR 0001 — 씬 전략: `SampleScene` 을 제자리에서 쓴다

- 날짜: 2026-08-03
- 상태: 채택
- 맥락: LOOP 부트스트랩 §4.5

## 결정

**`SampleScene` 을 복제하거나 별도 게임 씬으로 승격하지 않는다.** 제자리에서 그대로 쓰고,
파괴적 변경만 금지한다.

LOOP 문서 §4.5 의 기본 전략은 "Sample Scene 은 참조용으로 보존하고, 실제 게임 씬은 별도 경로로
승격한다" 였다. 이 프로젝트에서는 그 전략이 얻는 것이 없고 잃는 것이 있어 바꾼다.

## 사유

**1. 이 씬은 참조 자료가 아니라 이미 프로덕션 진입점이다.**
`SessionSceneRouter.SceneByMap` 이 `"backrooms"` → `SampleScene` 로 라우팅한다. 로비에서 방을
만들어 게임을 시작하면 열리는 씬이 이것이다. 복제해서 승격하면 라우터 표·`Game:Maps` 등록·export
경로를 새 이름으로 전부 다시 맞춰야 하고, 그 과정에서 R-0.1(맵 이름 불일치)과 **똑같은 종류의
정합성 사고**를 한 벌 더 만든다.

**2. 씬에 옮길 로직이 없다.**
씬 파일은 1080줄이지만 오브젝트가 9개뿐이다. 레벨·캐릭터·목표물·HUD 가 전부 런타임에 코드로
만들어진다 — `BlockRig` 가 몸을, `BackroomsMapGenerator` 가 레벨을, `MatchBootstrap.Awake/Start` 가
`MatchManager`·`DeviceSystem`·`GameHudController` 를, `MatchManager.PlaceObjectives` 가 목표물을
만든다. 씬은 **무엇을 만들지 가리키는 포인터**에 가깝다.

즉 §4.5 가 요구하는 "공통 로직을 씬 비의존 컴포넌트로 추출" 은 **이미 되어 있다.** 추출할 것이
씬에 남아 있지 않으므로, 씬을 나누는 작업은 순수한 중복 생성이다.

**3. 밸런스 수치도 씬에 없다.**
`Assets/Settings/GameConfig.asset` 에 40개 필드로 있다. 씬을 복제해도 두 씬이 같은 에셋을
가리키므로 격리되지 않는다 — 복제가 주는 안전감은 실제로는 없다.

**4. 복제하면 두 벌이 갈린다.**
씬이 두 개가 되면 `BackroomsMapGenerator` 의 직렬화된 값(gridSize 35, cellSize 3, floors 2,
seed 0 …)이 두 곳에 있게 되고, 한쪽만 바꾸는 순간 export 한 `MapData/*.json` 이 어느 씬의
지형인지 알 수 없게 된다. 맵 해시가 그 커플링의 유일한 감시 장치이고, 그 해시는 씬 이름을
포함하지 않는다.

## 대신 두는 보호장치

복제로 얻으려던 "되돌릴 수 있음" 은 다른 수단으로 확보한다.

1. **git 이 참조본이다.** 씬을 되돌릴 필요가 생기면 `git checkout` 이 답이고, 이것이 씬 복제보다
   정확하다 — 복제본은 만든 시점에 고정되지만 git 은 모든 시점을 갖는다.
2. **씬 편집은 태스크당 한 건으로 제한하고 LOOP_PROGRESS 에 기록한다.** 씬 파일 변경이 들어가는
   태스크는 변경 예정 오브젝트를 계획에 명시한다.
3. **`MultiplayerTest` 씬은 건드리지 않는다.** 규칙 없는 몸만 필요한 개발 루프가 그쪽에 있으므로
   (`RemotePlayerPuppet` 은 `MatchManager` 가 있을 때만 매치 컴포넌트를 붙인다), 매치 작업이
   그 씬을 깨면 두 클라이언트 스모크 테스트 수단을 잃는다.
4. **이 ADR 이 허용하는 `SampleScene` 변경은 정합성 복구뿐이다** (R-0.1: `MapName` 을
   `"backrooms"` 로 통일 + export 재실행). 그것은 씬의 *의미* 를 바꾸는 변경이 아니라, 씬이
   이미 주장하는 것(`SessionSceneRouter` 가 `backrooms` 로 라우팅한다)을 참으로 만드는 변경이다.
   기능 추가로 씬 오브젝트를 늘리려면 새 ADR 을 쓴다.

## 결과

- 씬 복제 작업이 백로그에서 사라진다.
- 대신 R-0.1/R-0.2(맵 정합성 복구)가 **최우선 태스크**가 된다. 씬을 그대로 쓰기로 했으므로,
  그 씬이 서버와 같은 지형을 말하게 만드는 것이 다른 모든 작업의 선행 조건이다.
- `BackroomsMap.cs`(레거시, 어느 씬도 참조하지 않음)와 `backrooms2f.json`·`arena.json` 의 삭제는
  되돌리기 번거로운 변경이므로 **확인을 받고** 진행한다 → OQ-5.

## 대안 (기각)

| 대안 | 기각 사유 |
|---|---|
| `GameScene.unity` 로 복제 승격 | 위 1~4. 라우터·맵 등록·export 경로를 다시 맞춰야 하고 정합성 사고를 한 벌 더 만든다 |
| 씬 없이 코드로만 부트스트랩 | `BackroomsMapGenerator` 의 직렬화 값이 갈 곳이 없어진다. 씬은 그 값의 저장소로 실제 역할이 있다 |
| `MultiplayerTest` 를 게임 씬으로 승격 | 규칙 없는 두 클라이언트 스모크 테스트 수단을 잃는다 (보호장치 3) |
